## 1. Overview & Architecture

Vittam uses **Firebase Remote Config** to deliver soft (optional) and hard (forced) update prompts without pushing a new build. Version logic runs entirely on the client — Remote Config just serves version strings and flags.

### App Boot Flow

```
main()
  └─ Firebase.initializeApp()
  └─ VittamRemoteConfig.initialize()  ← fetch & activate RC
  └─ OfflineService.init()
  └─ runApp(ProviderScope → BillingApp)
        └─ route '/'  → VittamSplashScreen (min 2 s display)
              └─ updateCheckProvider  ← compares versions
                    ├─ update available?  → VittamUpdateDialog
                    │     ├─ optional: user can dismiss
                    │     └─ forced:  user cannot dismiss / go back
                    └─ navigate '/home' → _AppEntry
                          └─ session check → login / license / MainShell
```

> **Non-fatal design:** If Remote Config fetch fails (no internet, timeout), the app silently proceeds.
> `fetchAndActivate` errors are caught and logged with `debugPrint` only — users are never blocked by an RC outage.

## 3. File-by-File Reference

### 3.1 `lib/core/utils/semver.dart`

Parses strings like `"1.2.3"` or `"v2.0"` into a comparable `SemVer` object.

```dart
// Safe parse — returns null on invalid input
SemVer? v = SemVer.tryParse("1.2.3");

// Strict parse — throws FormatException on invalid input
SemVer v = SemVer.parse("v2.0"); // patch defaults to 0

// Comparison operators
v1 < v2   // older
v1 > v2   // newer
v1 >= v2  // same or newer
```

**Supported formats:** `1.2.3`, `v1.2.3`, `1.2` (patch defaults to `0`)

---

### 3.2 `lib/core/update/update_state.dart`

Immutable model passed from provider to UI.

```dart
// No update needed
return UpdateState.upToDate(currentVersion);

// Update available
return UpdateState(
  updateAvailable: true,
  forceUpdate:     false,
  currentVersion:  "1.0.0",
  latestVersion:   "1.1.0",
  dialogTitle:     rc.updateTitle,
  dialogMessage:   rc.updateMessage,
);
```

| Field | Type | Description |
|---|---|---|
| `updateAvailable` | `bool` | Whether a newer version exists |
| `forceUpdate` | `bool` | Whether to hard-block the user |
| `currentVersion` | `String` | Installed app version |
| `latestVersion` | `String` | Version from Remote Config |
| `dialogTitle` | `String` | Localised dialog heading |
| `dialogMessage` | `String` | Localised dialog body |

### 3.3 `lib/core/services/remote_config_service.dart`

Singleton accessed via `VittamRemoteConfig.instance`.

```dart
// In main() — call once before runApp
await VittamRemoteConfig.instance.initialize();
```

**Fetch intervals:**

| Build mode | `minimumFetchInterval` |
|---|---|
| `kDebugMode == true` | `Duration.zero` (instant) |
| Release | `Duration(hours: 1)` |

### 3.4 `lib/core/update/update_provider.dart`

Two `FutureProvider`s registered in Riverpod.

```dart
// Compute update state — read once per session via ref.listen in splash
final updateCheckProvider = FutureProvider<UpdateState>((ref) async { ... });

// Expose app version string anywhere in the widget tree
final appVersionProvider = FutureProvider<String>((ref) async { ... });
```

Usage in a `ConsumerWidget`:

```dart
// Display version
final versionAsync = ref.watch(appVersionProvider);

// React to update check result (in VittamSplashScreen)
ref.listen(updateCheckProvider, (_, next) {
  next.when(
    data:  _onUpdateData,
    error: (e, __) => _onUpdateError(e),
    loading: () {},
  );
});
```

```dart
// No-op when state.updateAvailable == false
```

## 4. Firebase Console Setup

**Path:** Firebase Console → `vittam-ffc4c` → Remote Config → Create configuration

### Parameters to add

| Key | Type | Initial Value | Purpose |
|---|---|---|---|
| `latest_version` | String | `1.0.0` | Newest version on Play Store |
| `minimum_supported_version` | String | `1.0.0` | Oldest allowed version — triggers force update below this |
| `update_title` | String | `नया अपडेट उपलब्ध है` | Dialog title (Hindi) |
| `update_message` | String | `बेहतर अनुभव के लिए कृपया ऐप को अपडेट करें।` | Dialog body (Hindi) |
| `force_update` | Boolean | `false` | Master force-update switch |
| `force_update_below_version` | String | *(empty)* | Force update for versions strictly below this |

> **After adding all parameters, click Publish changes.**

### In-app defaults (RC unreachable fallback)

| Key | Fallback value |
|---|---|
| `latest_version` | `""` → no dialog shown |
| `update_title` | `नया अपडेट उपलब्ध है` |
| `update_message` | `बेहतर अनुभव के लिए कृपया ऐप को अपडेट करें।` |
| `force_update` | `false` |

## 6. Update Logic Rules

Decision tree in `update_provider.dart`, runs every app launch:

| Condition | Result | Dialog type |
|---|---|---|
| `latest_version` blank or unparseable | No dialog | Silent |
| current ≥ `latest_version` | No dialog | Silent |
| current < `latest_version` | Update available | **Optional** |
| `force_update` = `true` | Forced (regardless of version) | **Force** |
| current < `minimum_supported_version` | Forced | **Force** |
| current < `force_update_below_version` | Forced | **Force** |
| RC fetch fails | Uses cached / default values | Non-fatal |

> **Warning:** Force update is permanent until the user installs the update. Test force update scenarios carefully before publishing RC changes.

## 7. How to Trigger an Update (Day-to-Day)

### Optional update prompt

1. Publish new APK/AAB to Play Store (e.g. version `1.2.0`).
2. In Firebase Console → Remote Config, set `latest_version` → `1.2.0`.
3. Click **Publish changes**. Users on older versions see the optional dialog on next launch.

### Force update (critical fix)

1. Publish fixed version to Play Store (e.g. `1.2.1`).
2. Set `latest_version` → `1.2.1` and `minimum_supported_version` → `1.2.1`.
3. Alternatively, set `force_update` → `true` for an immediate master override.
4. Click **Publish changes**. All users below the threshold are hard-blocked.
5. Once rollout is complete, set `force_update` back to `false` and publish again.

### Immediate testing in debug builds

`minimumFetchInterval` is `Duration.zero` in debug mode. Hot-restart the app after publishing RC changes and it picks them up instantly — no waiting.

## 9. First-Time Setup Checklist

Use this when setting up in a new environment or after cloning the repo.

| # | Step | Command / Action |
|---|---|---|
| 1 | Install Firebase CLI | `npm install -g firebase-tools` |
| 2 | Log in to Firebase | `firebase login --no-localhost` |
| 3 | Activate FlutterFire CLI | `dart pub global activate flutterfire_cli` |
| 4 | Run flutterfire configure | `flutterfire configure --project=vittam-ffc4c` (from `frontend/`) |
| 5 | Verify `firebase_options.dart` generated | Check `lib/firebase_options.dart` exists |
| 6 | Verify `google-services.json` placed | Check `android/app/google-services.json` exists |
| 7 | Get dependencies | `flutter pub get` |
| 8 | Add RC parameters in Firebase Console | See [Section 4](#4-firebase-console-setup) |
| 9 | Run the app | `flutter run` |

### FlutterFire CLI path issue on Windows

If `flutterfire` is not recognised as a command, run it via its full path:

```powershell
& "$env:LOCALAPPDATA\Pub\Cache\bin\flutterfire.bat" configure --project=vittam-ffc4c
```

Or add `C:\Users\<you>\AppData\Local\Pub\Cache\bin` to your system `PATH`.

### Firebase login without localhost (other device)

```powershell
firebase login --no-localhost
```

Opens a URL — paste it into any browser on any device, authenticate, copy the code, and paste it back into the terminal.
